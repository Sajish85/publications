GPU telemetry-loss alerts for NVIDIA dcgm-exporter: rules, tests and a short technical note (v1.0)

Abstract

Three Prometheus alert rules that fire when GPU telemetry from NVIDIA dcgm-exporter stops arriving, with promtool unit tests, mutation tests and a short technical note. The two cases that matter most:(1) The exporter answers scrapes but serves no GPU series. dcgm-exporter's /health handler writes OK without checking DCGM collection (server.go lines 616&ndash;642 at tag 4.9.0), so up stays 1 and every GPU alert loses its input.(2) A short exporter blackout, such as a pod replaced by its DaemonSet within about a minute (modelled on krkn Scenario C), should not page. A unit test asserts that it doesn't. Rules: DCGMExporterDown (up == 0), DCGMExporterTargetsMissing (absent(up{...})), DCGMExporterNoGPUMetrics (up == 1 unless on (instance) DCGM_FI_DEV_GPU_UTIL_RATIO). The main file uses dcgm-exporter 4.9.0 metric names. A 4.8.x variant is included. Testing disclosure: validated with promtool unit and mutation tests on synthetic series; metric names checked against the exporter's default counters; not run against a live exporter or GPU. Contents: rule files (4.9.0 and 4.8.x), 6 unit cases per file, a 4-mutant check, a cross-check showing the metric-name port matters, the raw output of every check (TEST-OUTPUTS.md), the metric-name evidence (METRIC-NAMES.md), copies of the upstream files the checks relied on, and the note (PDF). Run everything with: make test. Tested with promtool 3.5.0. No GPU, exporter, cluster or Prometheus server was involved.
